# 模块整理：常量收敛 + 注释修正

对 $ARGUMENTS 模块执行两项整理（先 A 后 B，顺序不可换——常量轮会产生新注释，注释轮统一收口）：

- **任务 A（常量收敛）**：将模块中散落的运行时参数常量收敛到 `<模块目录>/<模块名>.Const.cs`，作为 `<模块名>` partial 分部类的常量成员（单一事实源）
- **任务 B（注释修正）**：全量修正模块注释至"最小可用"风格——修过时残留 + 压缩冗长注释

参考先例：网络模块 `NetworkModule.Const.cs`（5 分区 16 常量）+ 注释全量修正（本轮 -50% 冗余）。

## 纪律（全程）

- **阶段 1 盘点结果先汇报、排除项让用户拍板，再动手**
- 每步编译验证：`unity-cli tool call refresh_assets` → 轮询 `get_compilation_state` 至 `isCompiling: false` → `errorCount: 0`
- 多文件批量文本替换用 **python 临时脚本文件**执行（不要内嵌 heredoc，多行转义易错）；替换大小写敏感，禁用 PowerShell `-replace`
- 提交前必须先询问用户

## 任务 A：常量收敛

### A1. 盘点

```
grep -rn "const \|static readonly" <模块目录> --include="*.cs" | grep -v meta
grep -rnE "Delay\([0-9]{2,}|CancelAfter\([0-9]+\)|BufferSize|= [0-9]{2,}f?;" <模块目录> --include="*.cs" | grep -v meta
```

**判定标准**：

| 搬入 Const 分部 | 不搬（就地保留） |
|---|---|
| 运行时可调参数：间隔/超时/上限/阈值/缓冲大小/容量 | 方法内 `const string errorMessage`（就地错误文案） |
| 重复定义的同一常量（多处各自声明同一值——重点揪出） | 单位换算式（`* 1000` 等） |
| 可写 `static` 属性包装的参数（转 const，先确认全项目无写入方） | 类型标识符（`EventId = typeof(X).FullName` 等） |
| 带默认值的 API 参数且全项目无定制调用方（配合 A4） | Editor-only 工具常量（调试面板自包含） |
| | 生成物（AutoGen） |

### A2. 设计

- 文件：`<模块目录>/<模块名>.Const.cs`，`<模块名>` partial 分部类的常量成员（引用形态 `<模块名>.XXX`）
- `#region` 按语义分组（缓冲/超时/间隔/上限等），每常量 `/// <summary>` 写明**取值依据与单位**
- 命名 PascalCase、语义完整；模块主类若非 partial 改为 partial

### A3. 迁移

创建 Const 分部 → 逐常量搬入 → 全项目引用切为 `<模块名>.XXX`（含 `<see cref>`）→ **删除本地死声明**（const 行 + 前置 `///` 注释块 + 后置空行）

### A4. 参数链删除

API 带默认值参数且全项目**无定制调用方**：删参数，内部直取 Const 常量（YAGNI——不为假想灵活性留参数）。沿调用链删干净：签名 → 实现 → 构造函数 → 下游工厂 → `<param>` 文档注释。

## 任务 B：注释修正（"最小可用"风格基准）

### B1. 基准定义

- 类注释：3~5 行（职责 + 边界），删"功能：1.2.3."罗列与历史沿革
- 成员注释：一句话 summary；`<param>` 仅在含义不自明时保留；保留**单位/边界/关键 why/坑位**一句话
- 行内 `//`：保留 why 与坑，删与代码自明的步骤叙述
- `<example>`/`<remarks>`：public API 主文档可保留，内部实现删

### B2. 过时残留扫描（grep 模式，逐个判定）

- 旧命名残留：被更名/重构掉的类型名、目录名、旧 API 签名
- 已删除功能的描述：搜被删功能的关键词（开关/字段/方法名）
- 悬空注释：删除字段/成员后残留的 summary 块（`/// summary` 后紧跟空行的孤立块）
- 语义漂移："基类 abstract"（已接口化）、"覆盖默认值"（参数层已删）等与现行结构不符的措辞

### B3. 执行

逐文件 Read → 只改注释行（代码行绝不触碰）→ 保留有价值内容（设计动机的"原实现是 X"对照、锁序说明、线程模型说明均属高密度 why，保留）。
