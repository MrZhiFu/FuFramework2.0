# Git 提交规范

本文件是 Git 提交规范的**单一事实源**（原 `Docs/Git提交规范.md` 已并入并删除）。本文件无 `paths:`，每次会话常驻。

## 铁律：提交前必须问用户

- **任何 `git add` / `git commit` / `git push` 前，必须先列清单征得用户明确同意**，不得擅自执行。
- 任务完成后**不自动提交**，经用户验证确认后再统一整理提交。
- **非本次会话产生的改动绝不纳入提交**——提交前核对暂存内容，只提交本次会话改动的文件。
- 执行 `git add -A` 前必须核对没有其他会话/任务的文件夹带进来。

## 格式

所有 commit 遵循 Conventional Commits，描述用中文：

```
<type>: <中文简短描述>
```

## 类型

| 类型 | 用途 |
|---|---|
| `feat` | 新增功能 |
| `fix` | 修复 bug |
| `docs` | 文档更新（README、注释等） |
| `style` | 代码格式调整（不影响功能） |
| `refactor` | 重构（不新增功能、不修复 bug，仅优化结构） |
| `perf` | 性能优化 |
| `test` | 测试相关 |
| `chore` | 构建过程或辅助工具变动 |
| `build` | 构建系统修改 |
| `ci` | CI/CD 配置修改 |
| `revert` | 回退提交 |

## AI 提交标记

**Claude Code 生成的提交，Subject 开头必须加 `[AI]` 前缀**：

```
[AI]<type>: <中文简短描述>
```

人类提交不加此标记，以便区分提交来源。

## 示例

```
feat: 新增背包道具排序功能
[AI]fix: 修复登录界面偶发崩溃
docs: 更新红点系统README
[AI]refactor: 拆分 FsmModule 为 partial class
```
