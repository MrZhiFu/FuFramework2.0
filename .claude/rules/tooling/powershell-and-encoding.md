# 脚本与编码陷阱

本节三条都是**实际踩过并造成破坏**的坑。

## 1. Write 工具产出的 .ps1 无 BOM

PowerShell 5.1 在中文 Windows 上按 **ANSI** 读取无 BOM 脚本 → 中文字面量乱码破串。

- **对策**：脚本内字面量**一律纯 ASCII**。
- 需要中文输出时，用 `-Encoding utf8` 显式写出，或把中文交给调用方。

## 2. `-replace` 大小写不敏感

`-replace` 默认大小写不敏感，批量改名会**吞掉仅大小写不同的类型名**。

- **对策**：批量改名用 **`-creplace`**，改完立即编译验证。
- 同理适用于任何按正则做的批量文本替换。

## 3. Edit 工具的空白转换危险

历史事故：把 `new_string` 传成空串，删光了整个文件的缩进（两次）。

- **对策**：Tab/空格互转、批量缩进调整**一律用脚本做**（PowerShell/perl），做完 diff 验证。
- 不要用 Edit 工具做整块空白调整。
- 记住本项目缩进是 **Tab**，且 `.editorconfig` 固化 `insert_final_newline = false`——文件末尾无换行是约定形态。

## 4. 中文脚本的编码验证

写含中文的脚本后，跑一次看输出是否乱码；Grep/Read 看到的正常不代表 shell 执行时正常。
