# 框架模块下沉热更（极简启动器重构）— 设计文档

- 日期：2026-07-11
- 状态：待评审
- 主题：将 AOT 框架模块尽可能下沉到 Hotfix，使框架代码可热更

---

## 1. 背景与目标

### 现状
项目基于 **HybridCLR** 实现 C# 热更，代码分为 AOT 层与热更层：

- **AOT 层**（`Scripts/FuFramework/` + `Scripts/AOT/`，打进包体、不可热更）
  - 模块系统本体 `ModuleManager` / `ModuleBase`（位于 `Core/Runtime/Framework/`）
  - 14 个框架模块程序集：ReferencePool、ObjectPool、FSM、Procedure、Event、Mono、Timer、Asset、UI、Core、Launcher、ModuleSetting、Variable、TaskPool
  - 启动引导：`Launcher`（场景 MonoBehaviour）→ 9 个 `ProcedureXxx` 流程链 → 下载资源、加载 `Hotfix.dll`
  - `GlobalModule`（位于 Launcher 层）暴露已注册 AOT 模块给热更层访问
- **热更层**（`Scripts/Hotfix/`，编译为单一 `Hotfix.dll`、可热更）
  - 已在热更的 12 个框架模块：Config、Download、Entity、Guide、Localization、Model、Network、RedDot、Scene、Sound、Storage、Web（无独立 asmdef，均为 Hotfix 程序集内的文件夹）
  - 游戏业务逻辑：`Hotfix/Game/`

HybridCLR 配置中 `hotUpdateAssemblyDefinitions` **仅含 `Hotfix` 一个程序集**（guid `00a5234a2895a5544965dce970e4e128`）。

### 核心约束
1. **HybridCLR 引用规则**：热更层可引用 AOT，AOT **绝不能**引用热更层。
2. **当前 AOT 启动引导本身依赖模块系统**：下载/加载阶段用到了 `AssetModule`、`EventModule`、`UIModule`、`Procedure`/`FSM` 等模块来完成"下载资源 + 加载 DLL + 显示加载界面"。
3. **ScriptableObject 类型无法热更**：`ModuleSetting` 体系（AssetSetting/EntitySetting/GuideSetting/RedDotSetting/SoundSetting/StorageSetting 等）继承 `ScriptableObject` 且有序列化 `.asset` 文件，序列化引用 MonoScript GUID，热更类型无对应 MonoScript，故必须留在 AOT。
4. **`ModuleBase` 已是纯 C# 类**（源码注释："纯 C# 类，不依赖 MonoBehaviour，由 ModuleManager 统一驱动"），模块经 `Activator.CreateInstance` 反射创建、不参与场景/预制体序列化 → 下沉热更无 MonoBehaviour 序列化风险。（注：CLAUDE.md 中"继承 MonoBehaviour"的描述已过时，本次一并修订。）

### 目标
把 AOT 层收缩到「**下载资源 + 加载 DLL + 显示进度**」的最小自包含启动器，**不依赖任何框架模块系统**；模块系统本体与几乎所有框架模块下沉到单一 `Hotfix` 程序集，最大化可热更代码范围。

---

## 2. 关键决策

| 决策项 | 选择 |
|---|---|
| 重构激进度 | **极简启动器**（最大化热更）：AOT 仅保留下载+加载 DLL 的最小启动器，模块系统与几乎所有框架模块下沉 Hotfix |
| AOT 加载界面 | **AOT 内精简 FairyGUI 界面**（保留现有外观，但从 UIModule/EventModule 解耦重写） |
| 程序集粒度 | **全部归入单一 `Hotfix` 程序集**（删除各模块 asmdef，只移文件），与现有 12 个热更模块一致，AOT 加载器/拷贝工具/HybridCLR 配置零改动 |
| 迁移策略 | **分阶段增量迁移**，每阶段保持可编译、编辑器可运行，可随时回退 |

## 3. 目标架构与模块归属

### 边界原则
AOT 只做「下载资源 + 加载 DLL + 显示进度」，不依赖模块系统；其余全部下沉单一 `Hotfix` 程序集。

### 14 个 FuFramework 程序集归属

| 模块 | 归属 | 说明 |
|---|---|---|
| **Core** | 留 AOT（微调） | 作为共享基础（FuLogger / Utility / Extension / Singleton / Serializer 等）。仅把 `Framework/`（`ModuleManager`、`ModuleBase`）迁出到 Hotfix。热更层引用 Core（hotfix→AOT 合法）。**FuLogger 明确保留 AOT，不热更。** |
| **ModuleSetting** | 留 AOT | ScriptableObject 体系 + 序列化 `.asset`，无法热更。热更层引用它。 |
| **Launcher** | 拆分 | `Launcher`（场景 MonoBehaviour）留 AOT 并瘦身；`GlobalModule` + 模块注册逻辑迁到 Hotfix。 |
| ReferencePool / ObjectPool / FSM / Procedure / Event / Mono / Timer / TaskPool / Variable | 移入 Hotfix | 纯逻辑模块，整体搬入 Hotfix 目录树，删除各自 asmdef。 |
| **Asset** | 移入 Hotfix | 完整 `AssetModule` 下沉；AOT 侧新增极简 YooAsset 引导助手。 |
| **UI** | 移入 Hotfix | 完整 `UIModule` 下沉；AOT 侧新增极简 FairyGUI 加载界面。 |

> 注：TaskPool、Variable 当前未在 `Launcher.Modules.cs` 显式注册（属被其他模块内部使用的支持库），随其引用方一并下沉 Hotfix。

### AOT 侧最终保留内容
1. `Launcher`（场景入口 MonoBehaviour，瘦身版）
2. `BootstrapProcess`（极简更新序列，UniTask 直连 YooAsset，替代原 9 个 `ProcedureXxx`）
3. `BootstrapAssetHelper`（极简 YooAsset 引导封装）
4. `BootstrapView`（极简 FairyGUI 加载界面，替代 `WinLauncher`，保留外观）
5. `IBootstrapView`（AOT 定义的加载界面句柄接口，供热更侧驱动加载界面）
6. HybridCLR 加载（`RuntimeApi` + `AOTGenericReferences`）
7. `Core`（基础工具/日志/单例）+ `ModuleSetting`

### 收益
可热更范围扩展到：**模块系统本体 + 11 个原 AOT 框架模块 + 已有 12 个热更模块 + 全部业务逻辑**。AOT 仅剩「启动器 + 基础工具 + 配置」，几乎不再随业务变动。

## 4. AOT 启动引导重写

### 现状 → 目标
当前引导为 9 个 `ProcedureBase` 流程类的链式状态机：
```
ProcedureLauncher → ReqRemoteUpdateConfig → InitPackage → GetPackageVersion
→ UpdatePackageManifest → CreateDownloader → DownloadPackage → UpdateDone → CodeHotfix
```
目标：用一条 UniTask 异步序列替代，直连 YooAsset，不依赖任何框架模块。

### 新增/重写组件

**① `BootstrapProcess`**（替代 9 个 Procedure 类）— 线性 async 流程：
```
请求远程更新配置 → 初始化资源包 → 获取版本号 → 更新清单
→ 创建下载器(有更新则弹确认框) → 下载(刷新进度) → 更新完成
→ 加载 AOT 补充元数据 + Hotfix.dll → 反射调用 HotfixLauncher.MainAsync(IBootstrapView)
→ 关闭加载界面 + 移交更新循环
```
每步异常直接在加载界面显示并支持重试。

**② `BootstrapAssetHelper`**（极简 YooAsset 封装）— 只保留引导期能力：
`InitPackage / UpdatePackageVersion / UpdatePackageManifest / CreateDownloader / Download / LoadRawFileBytes`（加载 DLL/AOT 字节）。完整 `AssetModule` 下沉热更。

**③ `BootstrapView`**（极简 FairyGUI 加载界面）— 保留现有 `WinLauncher` 外观（进度条、提示文本、更新确认框），但直接 init FairyGUI 包 + 直接方法回调，不继承 `ViewBase`、不用 `UIModule`/`EventModule`。实现 `IBootstrapView`。

**④ `Launcher` 瘦身**（保留 AOT 场景入口）：
- `Start()`：只启动 `BootstrapProcess`，不再 `RegisterModules()`。
- `Update/LateUpdate/FixedUpdate`：改为调用可空委托 `OnUpdate/OnLateUpdate/OnFixedUpdate`。
- 移交机制：`HotfixLauncher.MainAsync()` 里把热更侧 `ModuleManager.Update/LateUpdate/FixedUpdate` 赋给这些委托 → 移交后由热更模块系统接管帧驱动。

### 加载界面跨阶段
现有 `WinLauncher` 横跨"下载(AOT)→加载配置/UI(热更早期，显示 `LoadConfig...` 等提示)→登录界面打开时关闭"。

设计：AOT 定义 `IBootstrapView`（`SetTip(string)` / `Close()`），`Launcher` 将 `BootstrapView` 句柄经 `HotfixLauncher.MainAsync(IBootstrapView)` 传入热更侧（反射调用改为 `mainMethod.Invoke(null, new object[]{ view })`）。热更侧在加载配置/UI 期间用它更新提示文本，登录界面打开时调用 `Close()`。UX 与现状一致。

### 错误处理
引导期任何异常（网络失败、清单更新失败、DLL 加载失败）→ 记录日志 + `BootstrapView` 显示错误文案 + 提供"重试"按钮（复用现有更新确认框按钮）。移交热更后错误处理归各热更模块自身负责。

## 5. 模块系统迁移与程序集/引用清理

### 关键原则：命名空间保持不变
移入 Hotfix 的模块**沿用原命名空间**（`FuFramework.UI.Runtime`、`FuFramework.Event.Runtime` 等）。C# 允许单一程序集内多命名空间，因此**所有调用点的 `using` 与类型引用零改动**——这是把风险和改动量压到最低的核心手段。

### 物理落位
移入模块统一放到 `Scripts/Hotfix/Framework/<模块名>/`，与现有热更框架模块一致。

### 单模块迁移标准操作（逆依赖序）
对每个要移入的模块（`UI → Asset → Timer → Mono → Event → Procedure → FSM → ObjectPool → ReferencePool`）：
1. 确认 AOT 侧已无任何引用（引导重写后应为零）
2. `Scripts/FuFramework/<模块>/Runtime/*.cs` → `Scripts/Hotfix/Framework/<模块>/`
3. 删除该模块的 `Runtime.asmdef`（+ `.meta`）
4. 若有 `Editor.asmdef`（ReferencePool/ObjectPool/FSM/Event/Timer/UI/Asset 有）：把其引用从 `FuFramework.X.Runtime` 改为 `Hotfix`（Editor 程序集引用热更程序集合法）
5. 从 **AOT.asmdef** references 移除该模块 GUID
6. 从 **Hotfix.asmdef** references 移除该模块 GUID（类型已内化）
7. 把其 `RegisterModule` 调用从 `Launcher.Modules.cs` 迁到 `HotfixLauncher`（保持相对顺序）

### 模块系统本体迁移
- `ModuleManager` + `ModuleBase`：从 `Core/Runtime/Framework/` 迁出到 Hotfix（Core 其余留 AOT）。前置：AOT 已不再调用 `ModuleManager`。
- `GlobalModule`：从 `Launcher.Runtime` 迁到 Hotfix。调用方 API（`GlobalModule.UIModule` 等）不变。

### 注册逻辑合并到 HotfixLauncher
原 `Launcher.Modules.cs` 的 `RegisterModules()`（9 个）迁入 `HotfixLauncher.MainAsync()`，置于现有热更模块注册之前，统一注册序列：
```
[基础层] ReferencePool → ObjectPool → FSM → Procedure → Event → Mono → Timer
[资源层] Asset → UI
[业务框架层] RedDot → Guide → Storage → Localization → Model → Config
           → Scene → Sound → Entity → Download → Web → Network
```

### 迁移后 AOT.asmdef 最终引用
仅保留：`FuFramework.Core.Runtime`、`FuFramework.ModuleSetting.Runtime`、FairyGUI、YooAsset、HybridCLR、UniTask（及 protobuf 等引导必需项）。

## 6. 分阶段迁移计划与验证点

**依赖约束**：①AOT 引导必须先戒掉模块系统，才能迁走模块系统；②迁移期"热更模块 → 引用 AOT 的 ModuleBase"合法，故 `ModuleBase`/`ModuleManager` 最后迁；③每阶段结束项目必须可编译、编辑器可进游戏。

> 验证方式：本项目无自动化测试。验证 = ①Unity 无编译错误 ②编辑器 `EditorSimulateMode` 进到登录界面（加载外观/进度/更新框一致）③最终阶段额外做一次真机/离线热更包验证 DLL 加载与移交。Unity 由开发者运行；AI 负责代码与引用一致性。

### Phase 0 · 基线
确认当前编辑器能进游戏、HybridCLR 出包链路正常，作为回归基准。

### Phase 1 · AOT 引导重写（模块系统原地不动）
- 新增 `BootstrapAssetHelper` / `BootstrapView` / `BootstrapProcess` / `IBootstrapView`；`Launcher` 改用委托驱动并启动 `BootstrapProcess`。
- 删除旧的 9 个 `ProcedureXxx` 流程类与旧 `WinLauncher`（ViewBase 版）。
- `HotfixLauncher.MainAsync` 改为接收 `IBootstrapView` 句柄，替代原 `WinLauncher` 相关调用。
- 集成要点：`BootstrapAssetHelper` 初始化 YooAsset 后，热更侧 `AssetModule.OnInit` 改为复用已初始化的 YooAsset/默认包，避免二次初始化。
- 此阶段 `ModuleManager` 仍在 AOT，9 个基础模块仍由 AOT 注册与驱动。
- **验证点**：编辑器进游戏到登录，外观与进度一致。

### Phase 2 · 逐个下沉游戏期模块（ModuleManager 暂留 AOT）
按逆依赖序逐个迁移已注册模块：`UI → Asset → Timer → Mono → Event → Procedure → FSM → ObjectPool → ReferencePool`。
每个模块执行第 5 节标准操作，注册调用迁至 `HotfixLauncher`（保持相对顺序）。
未显式注册的支持库 `TaskPool`、`Variable` 随其引用方（如 Asset/Event 等）一并下沉，无需注册调用，仅执行文件迁移与 asmdef/引用清理。
- **验证点**：每移完一个模块编译 + 编辑器进游戏一次（细粒度回归，出错即定位到单个模块）。

### Phase 3 · 迁移模块系统本体 + 更新循环移交
- `ModuleBase`/`ModuleManager`（Core→Hotfix）、`GlobalModule`（Launcher→Hotfix）迁移。
- `Launcher.Update/LateUpdate/FixedUpdate` 改为调用委托；`HotfixLauncher` 把 `ModuleManager` 帧驱动赋给委托完成移交。
- 移除 AOT 侧 `RegisterModules()`，全部注册归 `HotfixLauncher`。
- 清理 AOT.asmdef / Hotfix.asmdef 残留引用。
- **验证点**：编辑器 + 一次真机/离线热更包完整跑通（DLL 加载、移交、帧驱动、进游戏）。

### Phase 4 · 收尾
- 删除 `Scripts/FuFramework/<已迁模块>` 空目录与残留 `.meta`。
- 更新 CLAUDE.md / 架构文档 / 相关 README 中过时描述（ModuleBase 纯 C#、AOT/热更边界、模块归属表）。
- 最终全量回归。

## 7. 风险与缓解

| 风险 | 缓解 |
|---|---|
| YooAsset 双重初始化（引导助手 + AssetModule） | `AssetModule.OnInit` 检测已初始化则复用默认包，不重复 `YooAssets.Initialize()` |
| 加载界面跨 AOT/热更两阶段的控制 | AOT 定义 `IBootstrapView`，经 `MainAsync` 句柄传入热更侧驱动与关闭 |
| Editor 程序集引用失效 | 有 Editor.asmdef 的模块把引用改指向 `Hotfix` |
| Hotfix.asmdef / AOT.asmdef 残留悬空 GUID 引用 | 每次迁移同步清理两侧 references |
| 模块注册顺序被打乱导致依赖初始化错误 | 逆依赖序迁移 + 在 HotfixLauncher 保持统一注册序列 |
| AOT 泛型元数据缺失（模块下沉后新泛型实例化） | 迁移后重新生成 `AOTGenericReferences` / `link.xml`，真机验证 |
| 大范围改动难定位问题 | 分阶段 + 每移一个模块即回归 |
