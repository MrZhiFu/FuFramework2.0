# 多语言按语种拆分导出与加载 — 设计文档（v2，第一期）

日期：2026-11-18
状态：**已实施完成**（e8ca90ba + 64e643c7 + 8fb683a2）；第二期扩展见 `2026-11-20-多语言拆分并入Luban与字段剥离-design.md`

## 一、意图与背景（Why）

当前本地化配置导出为单文件（`tblocalization.json` / bin 变体 `.bytes`），每行携带全部 15 个语种字段。运行时整表常驻内存，其中 14/15 的语种文本对当前语言毫无用处——纯冗余。

定位（用户裁定）：**为未来数据量做好架构，顺带省包体/下载体积**。当前表只有 24 行（约 14KB），收益尚小；本改造为 SLG 规模（成百上千行文本）预留架构。

## 二、目标 / 非目标 / 反目标

**目标**
1. 导出产物按语种拆分：每个语种一个文件，只含该语种文本（空缺导出时固化英语兜底）。
2. 运行时只加载当前语种文件，内存中不存在其他语种冗余数据。
3. 手动切换语言时，才异步加载目标语种文件；就绪后才广播语言切换事件。
4. 下载体积收益兑现：语种文件按语种独立 bundle + AssetTags 标记，AOT 首启下载器按当前语言 tag 过滤，只下载当前语种。
5. AssetModule 新增**通用运行时下载能力**（查询下载量→下载→加载编排），语言切换是第一个消费方（用户裁定：以后必有运行时下资源需求，归属 AssetModule）。
6. `ENABLE_BINARY_CONFIG` 两种变体（bin/json）对称支持。

**非目标**
- AOT 前置表（`tblocalizationaot`，12 行 / 5.7KB）不拆：Resources 全量进包体，拆了不省下载；且自包含解析重写不值。留全字段。
- 服务器侧（`Server/FuFramework.Config`）不动：拆分只做 client 导出链路。
- 不做已加载语种缓存：切换回旧语种重新加载（配置文件毫秒级，不值缓存机制）——用户裁定。
- **本次不做设置界面 UI**（用户裁定）：全仓不存在设置窗口，也无任何 `Language` setter 调用方。本次交付模块能力 + 临时验证入口；设置 UI 后续项目再做。

**反目标（出现即失败）**
- 切换语言后业务表（道具/成就/引导等 TranslateText 机制）翻成旧语言。
- 切换过程中 UI 读到空译文或 `[key]` 占位文本。
- 语言切换在加载/下载未完成时被静默吞掉（失败须有可观测结果）。

## 三、现状与约束

- 导出链路：`Config/gen-client-bin.bat` / `gen-client-json.bat` 两遍 Luban（client 热更表 + aot 前置表），热更表产物在 `Unity/Assets/Bundles/Config/`。
- 表结构：`Localization` bean 有 17 字段（key + is_code + 15 语种），代码由 Luban 生成。生成代码反序列化对缺失字段 throw、空串不 throw。
- 业务表多语言机制：业务表存多语言 key，`TableManager.SetTranslateText` 启动时按当前语言填充；`TableManager.Localization.cs` 分部订阅 `LanguageChangeEventArgs`，切换时全表重译。**事件时序是硬约束**：广播前新语言文本必须已可查询。
- 加载链路：`HotfixLauncher.LoadConfigAsync` → `TableManager.LoadAsync(loader)`；表名拦截点全仓唯一（`TableManager.cs:88` → `loader("tblocalization")`）。loader 是注入点，生成代码与 Luban 模板零改动。
- 模块时序（builder check 已验证）：`RegisterBaseModules`（含 `LocalizationModule.OnInit` 读语言）先于 `LoadConfigAsync` 执行——**启动期 loader 路由时语言必然已确定**，无需 PlayerPrefs 回退。
- 现有下载能力：AssetModule 只有加载类 API（Load/LoadScene/Instantiate），**无下载入口**；YooAsset 引擎支持（AOT 启动期 `LaunchAssetHelper.CreateDownloader` 即 `package.CreateResourceDownloader`，不带 tag=全量）。
- YooAsset 收集冲突约束（builder check 验证）：同一 AssetPath 被两个 collector 收集会 throw；Config 组 `CollectAll` 递归收集子目录——**拆分文件必须放 Config 目录之外**。
- 铁律约束：全程 UniTask、禁 LINQ、禁运行时反射、异步链须有生命周期所有者（`LocalizationModule` 持有 `CancellationTokenIssuer`，OnDispose Cancel）。

## 四、备选方案（用户已选 A）

**方案 A：按语种完整拆分**（已选）
拆产物 + 独立目录独立 bundle + tag 过滤下载 + loader 路由 + 异步切换。
收益：内存 1/15 + 首启下载只含当前语种 + 按需拉取。
代价：改动面最大（导出工具、打包配置、AOT 下载过滤、AssetModule 下载 API、切换异步化）；首次切到未下载语种需下载等待。

**方案 B：加载后裁剪** — 否决：下载体积没省，与定位不符。
**方案 C：拆产物但保持单 bundle** — 否决：与 A 机制相同只差 bundle 粒度，一步到位。

## 五、设计（方案 A 展开）

### 5.1 导出侧：C# 拆分工具

- **形态**（裁决）：`Tools/` 下新增 C# console 小工具（dotnet 构建，与 `Tools/Luban`、`Tools/CleanL10nKeys` 同构），不用 PowerShell——bin 变体要手写 Luban ByteBuf 二进制，C# 直接复用 `ByteBuf` 语义更可靠，且避开 PS 5.1 无 BOM 编码坑。
- 由 `gen-client-bin.bat` / `gen-client-json.bat` 在 Luban 导出完成后调用；bin/json 由参数区分。
- 输入：`Unity/Assets/Bundles/Config/tblocalization.json`（bin 为 `.bytes`）。
- 输出：`Unity/Assets/Bundles/Localization/` 目录下 **15 个**文件 `tblocalization_<语言枚举名>`（枚举 16 成员中 `Unspecified` 无表列，builder check 已纠正笔误）。
- 拆分规则：每行输出 17 字段（key/is_code/当前语种文本 + 其余 14 语种空串）——对齐生成代码结构，反序列化零改动；该语种为空/缺失时填英语值（英语也空则留空，与运行时兜底语义一致）。
- bin 变体输出 `.bytes`（记录数前置 + 逐行 key/is_code/15 语种字符串，ByteBuf 格式）；json 变体输出 `.json` 数组。
- **源文件不物理保留**（裁决）：留在 Assets 下会被 YooAsset 照常打包，下载不降反升；核对走 git 历史。工具生成到新目录后删除 `Bundles/Config/tblocalization.*`。
- **变体清理**（裁决）：工具删除输出目录中非当前变体的残留（bin/json 混跑时只留一套），避免两套同时被打包。

### 5.2 打包侧：独立目录 + 按语种 bundle + AssetTags

- `AssetBundleCollectorSetting.asset` 新增收集组 `Localization`：
  - `CollectPath: Assets/Bundles/Localization`（Config 组外，避开递归双收集 throw）
  - `PackRuleName: PackSeparately`（每语种一 bundle）
  - `AddressRuleName: AddressByFileName`
  - **AssetTags 按语种**（如 `ChineseSimplified`、`English`）——AOT 首启 tag 过滤与运行时按需下载的筛选依据。
  - 具体字段名以现有 asset 结构为准；按文件名打 tag 若需自定义 PackRule/TagRule 类，随实施补充 Editor 规则类。
- 路径常量：`Utility.Asset.Path.cs` **已有** `BUNDLES_DIRECTORY_LOCALIZATION_NAME_PLACEHOLDER = "Localization"` 与 `GetLocalizationPath`（builder check 发现既有占位），直接启用，默认扩展名按变体传参（`.bytes` / `.json`）。
- **非本地化 bundle 的 tag 口径**（实施时验证）：YooAsset tag 过滤语义为"含指定 tag 的 bundle"，需确认全量下载器如何兼容——若按 tag 列表过滤，则非本地化 bundle 须统一打基础 tag（如 `base`），AOT 下载器 tags=[base, 当前语言]。以 YooAsset 3.x 实际 API 为准。

### 5.3 AOT 首启下载：按语言 tag 过滤

- `LaunchAssetHelper.CreateDownloader()` 增加 tags 参数；`LaunchProcess.CreateAndDownloadAsync` 传入当前语言 tag。
- 语言来源：`LaunchLocalization.Language`（`InitializeAsync` 先于下载流程执行——启动 UI 文本已依赖它，时序天然满足）；新装机无偏好时 `LoadLanguagePreference` 回退 `FromSystemLanguage()` 产出具体语言，tag 恒具体，无需处理 Unspecified。

### 5.4 AssetModule：通用运行时下载能力

新增 API（在 `AssetModule.API.cs` 同层，签名细节计划时定）：

- **查询**：按 tag（或路径集）查询待下载字节数/文件数（YooAsset `GetDownloadSize` 系）。
- **下载**：创建 tag 过滤下载器 → `StartDownload` → await 完成；进度回调（`Action<float>`，与 LoadSceneAsync 同风格）；`CancellationToken` 必传（铁律 5）；并发调用防抖由消费方负责或模块内排队（实施定）。
- **模式分支**：`EditorSimulateMode` / `OfflinePlayMode` 下查询恒为 0、下载直接成功返回（无远程清单可下）。
- **失败语义**：返回带失败信息的结果对象（不 throw 不静默），重试策略交消费方（语言切换场景由临时验证入口提示）。
- 内部复用现有 `AssetModule` 对 package 的持有方式（`LaunchAssetHelper` 同源），不重复初始化。

### 5.5 加载侧：loader 层路由（生成代码零改动）

- `HotfixLauncher.JsonConfigLoader` / `BinaryJsonConfigLoader`：`file == "tblocalization"` 时路由到 `GetLocalizationPath($"tblocalization_{当前语言枚举名}", 变体扩展名)`，其余表名走原逻辑。
- 语言来源：`LocalizationModule.Instance.Language`（模块时序已验证，恒已确定）。
- 表替换走**原地重填**（裁决）：切换语言后直接再调 `TbLocalization.LoadAsync()`（loader 已按语言路由），DataList/StrKeyDataDict 原地重建；**不改 LocalizationProvider**（其缓存的表实例引用自动有效）。换新实例方案有坑（`ConfigModule.AddConfig` 对已存在 key 只警告不覆盖、`TableManager.TbLocalization` 属性 private set），已否决。

### 5.6 语言切换：异步加载 + 事件时序

`LocalizationModule` 新增 `SetLanguageAsync(ELanguage language)`（UniTask，取消令牌挂模块 `CancellationTokenIssuer`）：

1. 相同语言直接返回；
2. AssetModule 查询目标语种 bundle 下载量：为 0 直接进加载；不为 0 先下载（进度可上抛给 UI）；
3. 加载目标语种文件 → `TbLocalization.LoadAsync()` 原地重填；
4. **就绪后**才走现有 `Language` setter 流程（存档 + PlayerPrefs + 广播 `LanguageChangeEventArgs`）；
5. 广播后 `TableManager.OnLanguageChanged` → `RefreshTranslateText` 全表重译（现有机制不变）。

- 防抖：加载/下载中再次切换 → 旧链路取消（每次切换局部新 CancellationToken），以最新目标为准；模块生命周期兜底由 `CancellationTokenIssuer` 负责。
- 旧语言数据释放：原地重填自然丢弃；不缓存已加载语种（用户裁定）。
- **临时验证入口**（用户裁定）：调试面板（DebugWindowBase 系）加语言切换按钮组，按钮点击→调 `SetLanguageAsync`→完成后提示；标注临时，设置 UI 后续再做。

## 六、验收标准

1. 启动后内存本地化表仅含当前语种文本（探针验证行数据其余语种字段为空串）。
2. 调试面板切换语言：本地已有→即时切换；首次切到未下载语种→下载进度→完成后 UI 与业务表全切新语言；无旧语言残留、无 `[key]` 闪现；失败有可观测提示。
3. YooAsset 构建：15 个语种各自独立 bundle 且各带语种 tag；AOT 首启下载器只下载当前语种（tag 过滤生效，其余语种 bundle 不进首启下载队列）。
4. AssetModule 下载 API 在 EditorSimulateMode / OfflinePlayMode 下安全跳过（查询 0、下载直过）。
5. bin/json 两变体均通过；混跑后产物目录只留一套。
6. AOT 阶段启动文本不受影响（前置表未拆）。
