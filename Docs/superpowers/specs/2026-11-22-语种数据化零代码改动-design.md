# 语种数据化改造设计（删语种零代码改动）

> 日期：2026-11-22　|　状态：已实施（P0–P4 完成，Play 实测通过）

## 背景与目标

v3 多语言拆分（`fee02235`）后，"语言"仍散落在 7 类硬编码中：热更 Provider 的 15 分支 switch、AOT 的 15 分支 switch 与 16 列手写解析、两份 `SystemLanguage→ELanguage` 手写映射、AOT 偏好 int 范围校验、硬编码 English 兜底、YooAsset 每语种一个 collector。

**目标**：删除/新增语种 = 只改配置数据（本地化表语言列 + `TbLanguageDef` 行 + `__enums__` 枚举成员）→ 重跑 `gen-client-*` → 全链路生效，**不改任何非 AutoGen 的 C#**。"动态"指生成期数据化，非运行时热插拔。

## 用户裁定

| 裁定项 | 结论 | 理由 |
|---|---|---|
| 取词层形态 | **生成期访问器**（保留 16 字段产物） | key+value 需两套模板手术风险高；访问器同样达成零代码目标 |
| 兜底语种 | **写死 English，不做配置** | 业务不变量，做成配置引入"配错行"风险；English 不可删除（生成期校验兜住） |
| `legacy_id`/`code` 列 | **删除** | 项目未发布，int 偏好仅开发期存档，一次迁移即失效；code 纯预留无消费者 |
| 语种清单 | **方案 B：6 语种**（简中/繁中/英/日/韩/西），删 9 个 | 13 个未维护语种全部 74% 同步缺漏，说明"建了列没在用"；扩语种已数据化，加回零成本 |
| collector 同步 | **生成期自动 + 幂等脚本**（挂在 gen 脚本末尾） | Unity 开着时窗口有内存缓存，但仅自动刷新关闭/IsDirty 时有覆盖风险；Play 实测 refresh 后一致 |

## 架构

```
TbLanguageDef（+system_language 列）
        │ cs-language-registry（短调用 -t aot -o Tables.TbLanguageDef -f）
        ▼
LaunchLanguageRegistry（AOT 程序集，唯一语种事实源）
  ├─ Entries / Fallback="English" / FromSystemLanguage（数据驱动 switch）
  ├─ AOT: LaunchLocalization 选语种文件 / 偏好校验 / 系统语言
  └─ Hotfix: LocalizationModule.FromSystemLanguage（跨程序集按枚举名转换）

TbLocalization 语言列
        │ cs-l10n-accessor（client 段）
        ▼
LocalizationTextAccessor.GetText（Hotfix，case 随语言列自动增减）
  └─ LocalizationProvider 取词（删 15 分支 switch）

split-localization / split-aot-localization（dataPostprocess）
  └─ 每语种一文件（热更 .bytes / AOT key+value），删语种残留自动清理

sync_localization_yooasset_collectors.py（gen 末尾自动调用）
  └─ 枚举∩产物驱动重写 Config_Localization 组（幂等）
```

## 关键实现点

1. **P0 管线顺序**：`DefaultPipeline.ProcessTargets` 先 `LoadDatas()` 再启动 code target 任务——消除 `cs-l10n-key` 读 `FinalRecords` 的既有竞态，是注册表/访问器目标的数据可见性前提。
2. **注册表短调用**：`-t aot -c cs-language-registry -o Tables.TbLanguageDef -f`。`-o`（表全名）绕过分组过滤纳入 `-c-` 的 LanguageDef；`-f` 加载数据且不产出数据文件；产物进 AOT AutoGen（AOT 命名空间，Hotfix 引用 AOT，无反向依赖）。
3. **跨程序集枚举**：AOT 与 Hotfix 各持一份生成的 `ELanguage`（数值一致类型不同），传递须 `Enum.Parse(typeof(ELanguage), aot.ToString())` 按名转换。
4. **AOT 偏好**：字符串名存储（注册表校验）；旧 int 值 `(ELanguage)legacy + Enum.IsDefined` 一次性迁移后写回字符串；无效回落系统语言。
5. **校验（生成期失败即中断）**：枚举成员 ↔ LanguageDef 行 ↔ 本地化表语言列三方一致；English 必存；语言名唯一。负例实测：删 LanguageDef Thai 行 → `ELanguage 成员 'Thai' 在 LanguageDef 表中缺少对应行`。
6. **collector 同步**：驱动源 = 枚举成员 ∩ 拆分产物（**不 glob 目录**，残留会把已删语种加回来）；只替换 `Config_Localization` 组 Collectors 段；幂等；`--check` 模式供校验。
7. **横幅**：Luban 横幅列出实际挂载的 code target（`（code: cs-xxx, ...）`），区分同 bat 的多个 aot 段。

## 生成器脚本约定（血泪坑）

- **gen 脚本（bat/sh）必须无 BOM、纯 ASCII**：bat 中文注释在 GBK 代码页下行尾字节吞换行（历史坑 `6dd3cdfd`/`f700f494` 二次重演）；Python 改写脚本禁用 `utf-8-sig`（写回必带 BOM，`@echo off` 变乱码命令）。
- scriban 对 .NET 对象成员自动 PascalCase→snake_case；嵌套 ScriptObject 取属性失败 → 传标量。
- 改 Luban 模板/源码必须重跑 `build-luban.bat`（bin/Templates 才更新）。
- `-o` 匹配键是表**全名**（`Tables.TbLanguageDef`）。
- `PostProcessBase` 的单文件抽象重载必须实现（批量重载遮蔽不算实现）。

## 验收结论

方案 B 语种清理即实战验收：删 9 语种（Excel 删列/删行/删枚举成员）→ 4 个 gen 脚本 → 全链路生效：
- 拆分产物 15→6（含 `.meta` 自动清理）、collector 15→6、两份 ELanguage/注册表/访问器均 6 成员
- `git grep` 非 AutoGen 零语言硬编码残留；Unity 编译 0 错误；Play 实测登录正常无异常日志
- 唯一运行期阻塞是 collector 未同步（YooAsset `Found invalid asset`），由 gen 末尾自动同步解决
