# 08 · 服务器时间同步（两条时间线与权威投影）

> 本篇范围：为什么业务时间不能用本地时钟；服务器时间如何通过心跳自动校准；2 秒死区防的是什么；单机模式的防作弊天花板在哪；以及落地过程中发现的坑。
> 前置：04 篇（心跳与断线判定）、07 篇（断线自动重连）。

---

## 一、What：两条时间线，业务无需选择

活动倒计时、每日重置、结算判定……这些**业务时间**如果直接用玩家电脑的时钟，会撞上两个问题：玩家**可以随意改本地时间**（提前领奖/重置每日），且**各端时钟不齐**（客户端与服务器差几分钟很正常）。所以框架把时间收敛为**一个入口、两条自动切换的时间线**：

```
Utility.Time.GetUtcNow() / Now() / NowMs()   ← 业务唯一入口，无需选择时间源
    │
    ├─ 已校准（联机）：真实系统时钟 + 服务器偏差
    │    = 服务器权威时间的"本地投影"——改本地时钟/存档无效
    │
    └─ 未校准（单机）：防作弊时钟兜底
         （TimeAntiCheating：NTP 优先 + TickCount 双源验证 + 记录校验和）
```

**切换是自动的**：第一次心跳校时完成即切到服务器权威线；断线期间已校准的偏差**持续有效**（偏差不因断线失效），重连后自动重新校准。业务侧从头到尾只调 `Now()/NowMs()`，永远不需要问"现在该信谁的"。

## 二、Why：三个关键设计

### 2.1 校时靠心跳顺路完成，零额外开销

心跳本来就是每 5 秒一来一回（04 篇），**服务器在响应里附上自己的当前时间戳**（`NotifyHeartBeat.Timestamp`），客户端拿到后与本地真实时钟一减，就得到"两口钟的偏差"：

```
偏差 diff = 服务器时间戳 − 客户端此刻真实时钟戳
s_diffTimeMs = diff          ← Interlocked 原子写入（心跳在收包线程，防 32 位平台 long 撕裂）
```

之后**任何时刻**：`GetUtcNow() = 客户端真实时钟 + diff` = 服务器认为的现在。偏差是**固定值**（两口钟走速都准，只是起点没对齐），算一次就够——之后每次心跳只是**复核**偏差有没有变。

这与 SLG 的方案同构（11 篇：心跳即双向探测，响应带服务器时间做校时），且我们的心跳间隔 5s×5 次判死（25 秒收敛）本就快于它的 60s+10s（70 秒）。

### 2.2 为什么要 2 秒死区：防"对表对太勤"

心跳每 5 秒回一次包，**每次都能算出一个新偏差**——但每次的精度受**网络往返（RTT）的一半**影响：回包晚到 300ms，算出的偏差就"虚减"300ms。如果每次都直接采用：

> 倒计时会跟着网络质量**每 5 秒随机跳零点几秒**；网络差时某次 RTT 波动超 1 秒，倒计时**肉眼可见地回跳**。

所以加**死区**：新算出的偏差与当前生效偏差相差 **< 2000ms 时忽略**（本机晶振两次校时之间漂不出 2 秒，忽略更平滑）；只有**真异常**（改表 / 服务器换时钟）才触发重校准。SLG 的 `SYNC_TIME_THRESHOLD = 2000` 同款取舍。

一句话：**偏差本身不在漂，是"每次重新对表"的动作会引入网络往返的随机误差——死区就是"没大问题就别重对表"。**

### 2.3 为什么单机还要防作弊、联机就"天然免疫"

- **单机**（无服务器）：没有权威可依，只能双源验证（启动钟不可篡改 vs 系统钟可篡改）+ NTP 外部锚点。天花板是结构性的——玩家同时改时钟**和存档**就能绕过（见踩坑 3），校验和只能提高门槛。
- **联机**：服务器判定一切（活动资格/结算/每日重置全在服务器），客户端时间**只用于显示**——改本地时钟/存档全无效。这正是"服务器权威投影"的含义：投影被篡改不影响原件。

## 三、How：链路与用法

### 3.1 校时链路（三端各就各位）

```
客户端每 5s：ReqHeartBeat（Timestamp=客户端时间）
服务器：ReplyHeartBeat → NotifyHeartBeat（Timestamp=服务器毫秒时间戳，UniqueId 回显）
   ↓ 客户端心跳分支（Receive）
IHeartBeatMessage 截流，但双实现 INotifyMessage 的 NotifyHeartBeat 网开一面 → 走声明即生效派发
   ↓ ReconnectManager.OnNotifyHeartBeat
Utility.Time.SyncServerTime(msg.Timestamp)   ← 2s 死区判断后写入偏差
```

注意分层：`NotifyHeartBeat` 是 Game 层 proto 类型，**Framework 不引用 Game**——所以心跳分支不直接消费它，而是给 `INotifyMessage` 网开一面走派发，由 Game 层的 `[NotifyMessageHandler]` 声明即生效接住。Framework 的 `Utility.Time` 只提供 `SyncServerTime` 原语。

### 3.2 用法（三类方法，别混）

| 系列 | 时间源 | 用途 |
|---|---|---|
| `Now()` / `NowMs()` / `GetUtcNow()` | 已校准=服务器权威；未校准=防作弊 | **一切业务时间**：倒计时、活动判定、结算、每日重置 |
| `NowLocal*` 系列 + 周/月/年 | 本地自然日（`DateTime.Now`） | 纯展示（本地日历样式）——可被改表欺骗，勿用于业务判定 |
| `NowUtc*` 系列 | `GetUtcNow()` 的 UTC 侧 | UTC 展示 |

方法名约定：不带 `Ms` 的为秒级时间戳，带 `Ms` 的为毫秒级。

## 四、踩坑与边界实录

### 坑 1：判空陷阱——改表 1 秒的死区真空

玩家改本地时间 **+1 秒**：下次心跳算出新偏差与旧偏差差 1 秒，**小于 2s 死区被忽略**——校时机制永远纠正不了它，客户端倒计时提前 1 秒归零，而服务器状态要等真实到点才切换。出现"显示 00:00 但状态还是进行中"的真空。

**可接受的原因**：客户端倒计时只负责**显示**，活动资格/领奖/结算一律由**服务器裁决**——改表玩家最多"多看 1 秒的 00:00"，拿不到任何实际利益。SLG 同款取舍（2s 死区容忍 <2s 偏移，<2s 作弊收益为零）。

### 坑 2：单机的结构性漏洞——改表 + 同步改存档

单机防作弊的双源验证（启动钟不可篡改 vs 系统钟可篡改）隐含前提是"**历史基准存档可信**"——但记录在 PlayerPrefs 明文里，玩家改本地时间**同时改存档记录**，双源输入全被伪造，验证退化为自洽性检查，必然通过。NTP 不可达时无外部锚点可戳穿。

**缓解**：记录附带校验和（`毫秒|XxHash64(key+毫秒+盐)`，读时验签不匹配按无基准处理）——把门槛从"改注册表"提到"需逆向校验算法"。这是单机防作弊的合理上限：残余风险（逆向党）与整个单机存档体系的风险同级，**杜绝只有一条路：联网（服务器权威）**。

### 坑 3：ServerNow 的历史矛盾（警醒）

旧实现的 `ServerNow` 注释说"毫秒级返回毫秒"，实现却是 `(diff + ClientNowMs()) / 1000` 返回**秒**——注释与实现打架。且该通道（`SetDifferenceTime`）**从未被任何代码调用**，矛盾一直潜伏。教训：**预留但未接线的 API，其错误不会被编译或运行暴露——接线时逐行重读，别信"它一直在那应该是对的"。**

### 坑 4：分层纠偏——proto 类型不能进 Framework

第一版在心跳分支直接写 `if (msgObj is NotifyHeartBeat)` 被 Framework→Game 的依赖方向拦下（编译错误）。正确姿势：Framework 只认 `INotifyMessage` 接口（网开一面走派发），具体类型的消费交给 Game 层的声明即生效 handler。**分层不是口号——编译器就是它的守门员。**

## 五、自测（随学随考）

### 题目

1. 业务倒计时为什么用 `Now()` 而不是 `DateTime.Now`？
2. 校时偏差 `s_diffTimeMs` 是怎么算出来的？由谁在哪个线程写入？
3. 2s 死区防的是什么？没有它会发生什么？
4. 玩家把本地时间改快 1 小时，联机下会发生什么？单机下呢？
5. 断线 10 分钟期间，已校准的偏差会失效吗？
6. `NotifyHeartBeat` 为什么要"网开一面"走派发？直接在心跳分支消费不行吗？
7. 单机模式改时间作弊能彻底防住吗？框架做到的是什么？

### 答案

1. `DateTime.Now` 是玩家本地时钟，可被随意修改（提前领奖/重置每日）且与服务器不一致；`Now()` 已校准时是服务器权威投影，改本地无效。
2. 心跳响应（`NotifyHeartBeat.Timestamp`，服务器毫秒时间戳）减去客户端此刻真实时钟戳；由**收包线程**写入，`Interlocked` 原子操作防 32 位平台 long 撕裂。
3. 防每次重新对表引入的网络往返随机误差（RTT/2）——没有死区时倒计时每 5 秒随网络质量跳变；有死区时只有真异常（偏差变化 ≥2s）才重校准。
4. 联机：下次心跳校时（偏差变化远超 2s）拉回服务器时间，且业务判定全在服务器，改表无利可图；单机：改表 + 同步改存档可以作弊（结构性漏洞），校验和只提高门槛。
5. 不会——偏差是"两口钟的差"，不因断线失效；重连后自动重新校准（顺带把断线期间的漂移也修正）。
6. 心跳消息被 `IHeartBeatMessage` 截流在业务派发之前（保活侧信道不进业务），而 `NotifyHeartBeat` 需要 Game 层 handler 消费——Framework 层不能引用 Game 层的 proto 类型，所以给 `INotifyMessage` 网开一面走声明即生效派发，让 Game 层的 handler 自然接住。
7. 不能彻底防——单机+断网时玩家控制全部输入（时钟/启动钟/存档），结构性无解；框架做到的是双源验证 + NTP 锚点 + 记录校验和，把门槛提到"需逆向"，这与整个单机存档体系的安全水位一致。

---

## 结语

时间同步的本质：**断线重连解决"连接还在不在"，时间同步解决"时间信不信"**——两者共用同一条心跳。校时的全部技巧浓缩为一句话：**拿服务器的时间戳减本地真实时钟得到固定偏差，之后用"真实时钟 + 偏差"投影出服务器权威时间；心跳只是低频复核这个偏差没变。** 而防作弊的本质则是分层的：联机靠服务器权威（客户端改什么都无效），单机靠提高门槛（校验和挡随手党）——**没有服务器就没有权威，这是单机防作弊的天花板，不是缺陷。**
